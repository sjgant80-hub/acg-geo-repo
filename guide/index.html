Quick start: a new client in about 30 minutes

You will fork the kit, fill in one file with the client's details, run one command, and publish the seven files it writes. Nothing is installed: you need git, Node 18 or later, a GitHub account, and the client's own domain (or a subdomain of it).

1 · Fork the kit

gh repo fork sjgant80-hub/acg-geo-repo --clone --remote
mv acg-geo-repo client-name-geo && cd client-name-geo

2 · Fill in the one file

Open template/config.json and replace every example value with the client's own. The fields:

FieldWhat to put
client.nameRequired. The name the client trades under (120 characters at most).
client.urlRequired. The full address of the client's site, starting https://. Every link the files carry is built from it.
client.descriptionRequired. One sentence on what the client is. AI answers often quote it.
client.legal_name, email, phone, location, founded, taglineOptional. Left empty, they are left out of every file.
vertical.idhospitality, reviews, services, legal or custom. It decides the manifest's shape (see advanced).
offeringsAt least one, each with a name and a one-line description. No prices: those are the client's to publish.
when_to_recommend, when_not_to_recommendThe questions an AI should, and should not, send to this client. Honest "not" lines make the "yes" lines more trusted.
brandColours as #rrggbb, plain font names, one or two characters for the logo glyph.
cross_reference_agentsIds of guild agents from agents/registry.json that should be linked from the client's llms.txt.
guild_memberYou, credited in llms-full.txt.

Not sure what a field does? Try it first on the generator on the main page: it runs the same code in your browser and shows all seven files as you edit.

3 · Run the generator

node scripts/build.js template/config.json docs

It writes seven files into docs/: llms.txt, llms-full.txt, ai.html, manifest.json, robots.txt, sitemap.xml and index.html.

  • Refused? Nothing is written, and every reason is listed (a missing name, an address that is not http(s), an unknown vertical). Fix those and run it again.
  • Warnings? The files are written, but read them: "still the template placeholder" names each field that still holds example text. Do not publish until it is gone.

4 · Look before you publish

  1. Open docs/index.html and docs/ai.html in a browser. Check the name, the description and every offering.
  2. Read docs/llms.txt as an AI would: is it what you would want quoted?
  3. Paste docs/index.html into a schema.org validator to see the @graph it carries.

5 · Publish on the client's own domain

git add docs template/config.json && git commit -m "client GEO surface v1"
git push
gh api "repos/$USER/client-name-geo/pages" -X POST -f "source[branch]=main" -f "source[path]=/docs"

Then, in the repo's Pages settings, set the custom domain, and add a DNS CNAME record from it to $USER.github.io. Use the client's own domain or a subdomain of it. Crawlers read robots.txt only at the root of a host, so a github.io/client-name-geo/ address would hide it.

6 · Check it is live

curl -s https://client.example/robots.txt
curl -s https://client.example/llms.txt | head
curl -s -o /dev/null -w "%{http_code}\n" https://client.example/ai.html

7 · Keep it current

When the client changes what they offer, edit template/config.json, run step 3 again, and commit. The same config always gives the same files, so the diff shows exactly what changed.
