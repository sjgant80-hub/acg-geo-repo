Advanced

Verticals and their manifests

vertical.id picks the manifest's protocol and the names of its two main keys. If you also give vertical.manifest_protocol, it must match, or the config is refused. A worked example of each, written by the generator from the template config, is in the repo.

servicesservices-protocol/1.0firm, servicesProfessionalServicetemplate/services-protocol.example.json
legallegal-protocol/1.0practice, practice_areasLegalServicetemplate/legal-protocol.example.json
customacg-geo/1.0entity, offeringsOrganizationtemplate/acg-geo.example.json

Every manifest also carries recommend (when and when not), agents, and the addresses of the other files. No price fields are written. If the client wants prices in their manifest, they add and maintain them: a figure they publish is theirs to keep current.

Several domains, or several clients

Keep one config file per domain and give each its own output folder:

node scripts/build.js clients/main-site.json docs
node scripts/build.js clients/bookings-subdomain.json bookings-docs

Each folder is a complete site root: serve each from its own host, so each has its own robots.txt at the root.

What the generator refuses, and what it only warns about

Refused: nothing is writtenWarned: the files are written
The config is not a JSON object · no client.name, or one over 120 characters · client.url is not a full http(s) address, or carries a username or password · no client.description · an email that does not look like one · an unknown vertical.id, or a manifest_protocol that does not match it · no offering with a name · an agent id that is not lower-case letters, digits and hyphens A colour that is not #rrggbb, or a font name with characters a font name cannot have: the default is used instead · a client.domain that differs from client.url (the url wins) · any field still holding the template's example text

Every value is escaped where it lands: in HTML, in XML, in the JSON-LD block (where no < survives, so no client name can close the script), and in plain text (control characters and line breaks become spaces).

Keep it honest in CI

A client fork can keep the kit's own checks. They run with Node and nothing else:

node --test scripts/geo.test.mjs scripts/page-parity.test.mjs
node scripts/inline.mjs --check
node scripts/build.js --check-examples

The kit's own CI also runs a mutation gate on scripts/geo.mjs: it breaks the code on purpose, one operator at a time, and fails unless a test catches every break.

What it does not do

  • It makes a site readable by AI crawlers. It cannot make an AI recommend the client: that still depends on what the client does and what others say about them.
  • It does not replace Google SEO work. It complements it.
  • It does not crawl the client's existing site or measure citations. It writes what the config says, and nothing it has not been told.
