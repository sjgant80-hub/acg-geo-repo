What GEO is

SEO for the AI-answer era.

Search is shifting from Google's ten blue links to ChatGPT/Claude/Perplexity's one-cited-answer. Sites optimised for Google alone are invisible to those crawlers. GEO (Generative Engine Optimization) is the structural work that makes a site AI-readable · so an AI travel agent finds it, cites it, recommends it. The Guild ships this at every client engagement · this repo is the shared kit.

Layer 1

llms.txt manifest

A plain-text file at the root telling AI crawlers what the site is, what it sells, and when to recommend it. GPTBot, ClaudeBot, PerplexityBot read this before touching the HTML.

Layer 2

JSON-LD @graph

Full entity graph: Organization + WebSite + Person + Product / Service / Place. Machine-readable structured data every AI parser handles cleanly.

Layer 3

ai.html dossier

A machine + human readable page written FOR AI agents. Identity, offerings, contact, citation format, "when to recommend / when not to" guidance. The citation surface.

Layer 4

Domain manifest (stays-protocol style)

A custom JSON manifest AI agents can parse in ~50ms · listings, pricing, availability, whatever the domain needs. Guild members define their vertical's shape.

Layer 5

robots.txt allow-list

Explicit allow for the major AI crawlers · GPTBot, ClaudeBot, anthropic-ai, PerplexityBot, Google-Extended, CCBot, Bytespider. Front door open.

Layer 6

Agent marketplace listing

Add the client to the Guild's agent registry so other guild-owned agents can discover, cite, and route to them.

How it works

Check the config, then write every file from it.

The generator is one small file, scripts/geo.mjs. It takes no network calls and makes no AI-model calls. The same config always gives the same files.

Step 1 · check

Refuse a bad config

The name, a full http(s) address and a one-line description are required, plus at least one offering. The vertical must be one it knows. Colours must be #rrggbb and fonts plain names. A javascript: address, a colour that tries to break out of the CSS, or an unknown vertical is refused or replaced, with the reason.

Step 2 · write

Seven files from one record

llms.txt and llms-full.txt, ai.html, the vertical's manifest (stays, reviews, services, legal or custom), robots.txt, sitemap.xml and a client landing page. Both HTML pages embed the same schema.org @graph. Every value is escaped where it lands, so a client name cannot inject a script.

Step 3 · publish

Push, and the crawlers can read it

Commit the folder and serve it with GitHub Pages or any static host. robots.txt names the AI crawlers and points to the sitemap. llms.txt tells them what the client is, what it offers, and when to recommend it, and when not to.

How it is kept honest: the generator's tests are themselves tested by a mutation gate (every deliberate break must be caught), on GitHub's machines, on every change. The page runs the gated code byte for byte, and a test fails the build if this page lists a file the repo does not have. Prices are left out of every manifest: those are the client's to publish.

Deploy in ~30 min per client

Fork · config · build · Pages on.

The full walk-through, with the checks to run before you publish, is in the quick start.

# 1. Fork this repo (or the guild-branded fork of it)
gh repo fork sjgant80-hub/acg-geo-repo --clone --remote

# 2. Rename to the client
mv acg-geo-repo client-name-geo && cd client-name-geo

# 3. Edit ONE file · every artefact regenerates from this
$EDITOR template/config.json

# 4. Run the generator (Node 18 or later; no install, no dependencies)
node scripts/build.js template/config.json docs
# writes docs/: llms.txt · llms-full.txt · ai.html · manifest.json ·
#               robots.txt · sitemap.xml · index.html (client landing)

# 5. Commit + push + serve docs/ with GitHub Pages (or any static host)
git add docs template/config.json && git commit -m "client GEO surface v1"
git push
gh api "repos/$USER/client-name-geo/pages" -X POST -f "source[branch]=main" -f "source[path]=/docs"

# 6. Point client's domain (or subdomain) at Pages
#    Add CNAME record: client.example.com → $USER.github.io

Once live · every AI crawler that hits the domain reads the llms.txt manifest, parses the JSON-LD graph, and can cite the client accurately. No more "GPT doesn't know we exist."
